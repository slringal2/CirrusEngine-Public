# 川岸から見る流れと、浅い水の下の砂利

川岸で下を見ると、砂利が水を通して見える。視線を対岸へ向けると、草木や空の映り込みが水面を占める。今回手を入れたのは、映った景色を揺らす波の向き、浅い流れで波が細かくなる位置、川底をのぞいたときに見える砂利の位置である。

## C++ で掘った川が画面に届くまで

| 読む順 | 関数 | 入力と出力 |
|---|---|---|
| 1 | `World::terrainHeight` → `World::buildTile` | 地表の各 (x, z) で川筋までの距離を求め、浅瀬や砂州を含む河床の高さを決める。これが不透明な地形メッシュになる。 |
| 2 | `GeometryPS` | 地形メッシュに砂利の色と法線を当てる。あとで同じ画面位置から川底の深度と材質を読める。 |
| 3 | `Renderer::updateConstants` → `Renderer::frame` | `CameraTime.xyz` に視点、`.w` にシミュレーション秒、`WeatherEffects.yz` に風の速度を渡す。全画面三角形に `CompositePS` を適用する。 |
| 4 | `CompositePS` → `riverSurfaceDistance` | 画素ごとの視線と勾配付き水面の交点を取る。水が不透明な地形より手前にある画素で `shadeRiver` を呼ぶ。 |
| 5 | `shadeRiver` → `riverSurface` | 早瀬の波と泡、水を通して見える川底、岸と空の映り込みを求める。合成に戻り、カメラまでの空気・霧・雲を通す。 |

地形と水面が共有する高さは `riverLevel(z) = 123.4 − 0.0022 × z` m。1 km下流へ行くと2.2 m下がる。交点までの距離は `(riverLevel(camera.z) − camera.y) / (ray.y + 0.0022 × ray.z)`。C++とHLSLの両方から同じ河道定義をインクルードしている。[河道の定義](../../shaders/river_profile.hlsli) · [地形タイルの生成](../../src/world.cpp) · [C++のフレーム処理](../../src/renderer.cpp) · [水面との交差](../../shaders/common.hlsli) · [地形描画と最終合成](../../shaders/scene.hlsl)

## 曲がった川で波を運ぶ

`riverSurface` は下流方向の座標を `z`、横方向を `x − riverCenter(z)` とする。同じ横座標をたどって下流へ進むと、蛇行しながら同じ岸に沿って移動する。岸から離れるほど流れが速くなり、狭い区間でも速くなる。水面上を移動するノイズの計算は次の部分にある。[水面シェーダー](../../shaders/river_water.hlsli)

```hlsl
float phaseA = frac(CameraTime.w / period);
float phaseB = frac(phaseA + 0.5);
float blendA = 1 - abs(2 * phaseA - 1);
float u = p.z - meanSpeed * CameraTime.w;
float2 drift = (float2(phaseA, phaseB) - 0.5) * period * (speed - meanSpeed);
```

`u` は平均0.84 m/sで模様を運ぶ。局所速度と平均速度の差だけを `drift` で加える。これを無期限に積算すると、岸から川の中央に向かって模様が時間とともに引き延ばされる。そこで3.2秒周期の座標をふたつ、半周期ずらして同じ3Dノイズを読む。Aが初期位置に戻る瞬間にはAの重みがゼロ、Bが戻る瞬間にはBの重みがゼロになる。この二相の考え方はValveの水流の発表でも解説されている。ここでは川幅と岸からの距離で局所速度を決めている。[Valve・Water Flow in Portal 2](https://cdn.akamai.steamstatic.com/apps/valve/2010/siggraph2010_vlachos_waterflow.pdf)

川幅が狭く、水深がおおむね0.3～0.75 mで、岸から離れている地点では `riffle` が強くなる。ここに短い斜めの波を混ぜ、泡は流れていくノイズの山にだけ現れる。深い流れには長い波が残る。川の横座標は蛇行に従っているので、法線をワールド座標へ戻す際には河道中心線の勾配も使う。細波が遠方で画素より小さくなるときは、視線の浅さ、画面の高さ、水面までの距離から画素が覆う水面の幅を見積もり、周波数ごとに法線の振幅を弱める。

## 砂利が水を通して見える理由

`shadeRiver` には元の画素で見えた地形までの距離と、水面までの距離がメートルで届く。ふたつの差は斜めの視線に沿う長さで、岸の浅さを測るには長すぎることがある。そこで水深の推定値 `column` と水中の光路長 `path` を別に持つ。水深は距離差に `max(0, −ray.y − riverGrade × ray.z)` を掛けて求める。勾配に平行な川底なら、この換算はその地点の鉛直水深と一致する。

水面から4.5 m未満の推定水深、カメラから155 m未満では、`refract(ray, normal, 1 / 1.333)` で水中の方向を作る。水中レイを推定した底まで進め、到達点をカメラに投影する。その画素で実際の深度からワールド位置を復元し、予測点と近く、水中の河道内にある場合に川底の色と光路長を更新する。たとえば平坦な水面に法線から70°で入るレイは、水中で約45°へ曲がる。水深1.5 mなら、水中を進む距離は約2.1 mである。[HLSL の refract](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-refract)

水を通る距離が増すほど赤い光が先に減る。コードの `absorption` は光路長を使ったRGBの透過率で、`T = exp(−float3(0.56, 0.24, 0.19) × path)`。水中から届く色は `bottom × T + scatter × (1 − T)` になる。そこへフレネル係数 `0.0204 + 0.9796 × (1 − N·V)^5` に応じて反射を混ぜる。見下ろすと川底がよく見え、視線が水面に平行になると空と対岸が強く映る。[屈折・吸収・反射の実装](../../shaders/river_water.hlsli)

## 岸から確かめる

リポジトリ直下で次のコマンドを実行すると、対岸と川底を同じ画面内で見られる。

```powershell
.\out\vs\Release\CirrusEngine.exe --camera walk --spawn 53 25 --look -25 -14 --time 16.4
```

水の範囲だけを調べる場合は同じコマンドに `--debug-view 31` を加える。白い範囲は深度テストで水面が地形より手前になった画素。草や石が手前にあれば、その形で水面が切れる。[デバッグ表示の選択](../../shaders/scene.hlsl)

水面の交点は一定勾配の平面で、波はその照明法線を変形する。対岸の反射と屈折には画面内に描かれた物体の深度を使う。投影位置が画面の外、草木の上、予測した河床から離れた位置に来た場合は、元の画素の川底へ滑らかに戻す。水門による水位の変化、岩の裏にできる渦の移動、集光による川底の光模様を動的に解くには、流体や光を追う別の入力が必要になる。


## 流れが折り返す瞬間を数値で確認する

二相の片方の座標が周期の先頭へ戻る瞬間は、その相の混合重みが0になる。波用の連続な試験信号を使い、161地点、4種類の局所流速、41回の半周期境界でCPU上の式を検算した。境界の左右をそれぞれ0.001秒、0.0001秒、0.00001秒ずらして比較すると、最大の色差は0.01323、0.001323、0.000132と小さくなった。これは移流と混合の値の連続性を調べた結果で、画面上の反射のちらつきやフレームレートは含まない。 [シェーダーの二相移流](../../shaders/river_water.hlsli)
